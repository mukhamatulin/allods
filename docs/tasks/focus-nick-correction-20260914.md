# Задача: раздельные целевые ники по серверам

- Идентификатор: `focus-nick-correction-20260914`
- Источник запроса: пользовательская задача без идентификатора Redmine
- Файл основной правки: `src/allods_hpi_to_xlsx.py`

## Контекст

После добавления второго сервера общая конфигурация листов целей стала использовать ник `Нулёвый` для обоих отчётов. Цели должны зависеть от сервера:

- «Молодая Гвардия» (`601`) — сохранить `Ройс` и `Мгла`.
- «Наследие Богов» (`101`) — использовать `Нулёвый` в первом листе целей и сохранить пустой второй слот.

Выходные файлы, файлы состояния, API-запросы и публикация отчётов должны остаться без изменений.

## Критерии приёмки

1. Конфигурация сервера хранит собственный набор листов и ников целей.
2. Отчёт для shard `601` создаёт листы целей для `Ройс` и `Мгла`.
3. Отчёт для shard `101` создаёт лист цели для `Нулёвый` и пустой второй слот.
4. Общий запуск и выбор сервера через `--shard-id` используют соответствующий набор целей.
5. Незакоммиченные пользовательские XLSX/JSON-файлы не изменяются и не включаются в коммит.

## План

1. Проверить требование на текущей конфигурации и зафиксировать ожидаемый провал.
2. Перенести набор целей в `ShardConfig` и использовать его при генерации отчёта.
3. Выполнить синтаксическую, поведенческую и проектную проверки, затем провести финальный просмотр diff.

## TDD и проверка

В проекте нет отдельного тестового каркаса. Для изменения конфигурации будет выполнена inline-проверка контракта с RED/GREEN-циклом, затем `python -m py_compile`, проверка конфигурации и `git diff --check`. Полный сетевой запуск не нужен: он не добавляет доказательств для изменения локального соответствия ников серверам.
