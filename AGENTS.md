# Commit Message Format

- Если пользователь просит "описание для коммита", возвращать только готовый текст коммита без дополнительных пояснений в прошедшем времени отвечающем на вопрос 'Что сделано?'.
- Формат строго такой:
  1) первая строка: `type(scope): ...`
  2) пустая строка
  3) список через `- ...`
  4) детализация внутри пункта только через `1)`, `2)`, `3)`
- Если пользователь явно пишет "текст не менять", сохранять формулировки дословно.
- Не добавлять ничего до и после блока коммита.

# Дополнительно

- Общайся со мной на русском языке
- Не писать fallback логику для обратной совместимости.
- При длительной реализации или аналитике давай промежуточные итоги каждую минуту
- Всегда давай две оценки в часах, если я прошу тебя что-то оценить - чистую разработку и полный цикл
- Отвечай в полностью копируемом plain-text формате
- Используй только точечные правки (apply_patch) по ASCII-стабильным участкам (сигнатуры методов, имена переменных), не цепляйся за кириллические комментарии в контексте патча

# Git workflow для задач с правками

- Для каждого нового диалога или задачи, где нужно менять файлы, перед правками создавать отдельную ветку от текущей ветки.
- Формат имени ветки: `codex/<kratkoe-opisanie-zadachi>-YYYYMMDD-HHMM`.
- Перед созданием ветки проверять `git status --short` и не трогать чужие незакоммиченные изменения.
- Если в рабочем дереве уже есть несвязанные изменения пользователя, оставить их как есть и явно упомянуть это в ответе.
- Делать коммит после каждого осмысленного шага, который можно отдельно описать.
- Сообщение коммита должно кратко описывать выполненный шаг в прошедшем времени.
- Перед каждым коммитом по возможности запускать релевантные проверки, форматирование или тесты.
- Не коммитить несвязанные файлы и изменения пользователя.
- После завершения задачи пушить ветку в `origin`: `git push -u origin <branch>`.
- Если пуш невозможен из-за отсутствия доступа, сети или настроенного remote, сообщить об этом и оставить ветку с локальными коммитами.
- В финальном ответе указывать имя ветки, список коммитов, выполненные проверки и оставшиеся незакоммиченные изменения, если они есть.
